Tenferro.TypedTensor Type
julia
TypedTensor(array::AbstractArray)

A CPU tensor backed by tenferro-rs and implementing Julia's AbstractArray interface. Construction copies values in column-major order; Array(tensor) returns another independent copy. Supports arbitrary dimensionality and element types Float32, Float64, Int32, Int64, Bool, ComplexF32, and ComplexF64.

Tenferro.AutoTenferro Type
julia
AutoTenferro()

DifferentiationInterface backend for first-order gradients of scalar-valued functions built from supported tenferro operations on CPU arrays of Float32, Float64, ComplexF32, or ComplexF64. Supports tensor elementwise operations, reductions, shape operations and selected linear-algebra operations; gradients of scalar outputs, pullbacks and pushforwards for arrays or tuples of arrays. Differentiation uses tenferro-rs JVPs and VJPs, independent of ChainRules rules.

Tenferro.EagerContext Type

Owns an eager execution context shared by its tensors.

Tenferro.EagerTensor Type
julia
EagerTensor(ctx::EagerContext, data::AbstractArray{T})

An eager tenferro-rs tensor. Construction copies data into the given context. Tensors used in the same operation must belong to the same context.

Tenferro.EagerScalar Type
julia
EagerScalar{T}

A rank-0 eager result, such as the value of sum(x) or x[i] for an EagerTensor. It takes part in arithmetic with tensors and numbers like a scalar; s[] returns its value as a T. A scalar belongs to the same context as the tensors it was computed from.

Tenferro.AutoTenferroTraced Type

DifferentiationInterface backend using tenferro-rs traced graph transformations.

Tenferro.TracedContext Type

Owns the graph containing a collection of traced tensors.

Tenferro.TracedTensor Type
julia
TracedTensor(ctx::TracedContext, data::AbstractArray{T})

A node in a tenferro-rs computation graph for tenferro-rs built-in CPU element types. Construction copies the input; Array(tensor) compiles and executes the graph.

Tenferro.stopgrad Function
julia
Tenferro.stopgrad(x)

Return the value of x with gradient flow blocked: derivatives computed by AutoTenferro or AutoTenferroTraced treat the result as a constant. Eager tensors use the backend's detach; traced tensors are evaluated and re-inserted into their graph as constant inputs. Tuples and NamedTuples are processed elementwise, and other values are returned unchanged.

Tenferro.constant Function
julia
Tenferro.constant(ref, x)

Copy the array or number x into the context of tensor ref as a constant: it is an independent input of the graph, so no derivative flows into it. A number becomes a zero-dimensional tensor. The element type of x is kept; it must be one of Float32, Float64, ComplexF32, ComplexF64, Int32, Int64 or Bool.

Tenferro.context Function
julia
Tenferro.context(t)

Return the context (EagerContext or TracedContext) that owns tensor t. Tensors created in this context can be combined with t.

Tenferro.DifferentiableElement Type
julia
Tenferro.DifferentiableElement

Element types that tenferro-rs can differentiate: Union{Float32,Float64,ComplexF32,ComplexF64}. Arrays with these element types are the differentiable inputs of AutoTenferro and AutoTenferroTraced; tensors of other element types (Int32, Int64, Bool) are constants.

Tenferro.num_threads Function
julia
Tenferro.num_threads() -> Int

Number of CPU worker threads tenferro-rs kernels run on.

All tenferro-rs operations of the process share one CPU execution engine, which keeps its buffer pool and kernel plan cache between calls. Its thread count is taken from the TENFERRO_NUM_THREADS environment variable when the engine is first used (default 1, serial) and can be changed with Tenferro.set_num_threads.

Tenferro.set_num_threads Function
julia
Tenferro.set_num_threads(n::Integer) -> Int

Run tenferro-rs kernels on n ≥ 1 CPU worker threads (1 is serial) and return the new thread count. The shared engine is rebuilt with a new worker pool, so its buffer pool and kernel plan cache start empty. Tensors and contexts created before the change remain valid.

Threaded kernels may sum in a different order than serial ones, so results can differ in the last bits. Julia threads that use tenferro concurrently take turns on the engine.

Tenferro.dense Function
julia
Tenferro.dense(σ, W, x, b=nothing)

σ.(W * x .+ b), a dense (fully connected) layer: a weight matrix W (out × in), an input vector or matrix x (in or in × batch) and an optional bias vector b (length out). The result has the shape of W * x. Any of the operands may be a plain array as long as one is a tensor; arrays become constants of the tensor's context.

When all operands have element type Float32 or Float64 and σ is identity or NNlib.relu (with NNlib loaded), the product, the bias and the activation run as one native kernel, and pushforwards and pullbacks of any order are native kernels too. The derivative of relu at 0 is 0, as in NNlib. The matrix products call Julia's BLAS through libblastrampoline, so they run on BLAS.get_num_threads() threads. Other activations and element types compose W * x, the bias and σ.(...) from tensor operations, with the same results.

Examples

julia
using Tenferro, NNlib
ctx = EagerContext()
W = EagerTensor(ctx, [1.0 -2.0; 0.5 1.0])
y = Tenferro.dense(relu, W, [1.0, 1.0], [0.0, -2.0])   # [0.0, 0.0]
Tenferro.logitcrossentropy Function
julia
Tenferro.logitcrossentropy(ŷ, y; agg=mean)

Softmax cross-entropy of the logits ŷ against the targets y, with classes along the first dimension: the column losses -sum(y .* logsoftmax(ŷ; dims=1); dims=1) aggregated by agg, which is mean or sum. ŷ is a Float32 or Float64 tensor, and y (one-hot or probabilities) is a tensor or an array of the same size and element type. Trailing dimensions count as columns. This is Lux.CrossEntropyLoss(; logits=Val(true), agg) without label smoothing. The result is a scalar of the logits' context.

The loss, its gradient and its pushforward each run as one native kernel. Second derivatives through the softmax (for example a Hessian with respect to ŷ) are not implemented and throw an error.

Element-type conversion and rounding use Base's functions on tensors: S.(x), convert(EagerTensor{S}, x), float., real., imag., trunc., floor., ceil., round. (also round.(S, x, mode)) and x .% S. Value-dependent conversions throw InexactError on eager tensors and ArgumentError on traced tensors; see Element-type casts and constants.

The NNlib, SpecialFunctions and ChainRulesCore package extensions add methods to those packages' functions and export no names of their own; see Operation contracts. With NNlib loaded, this includes activations, softmax, batched_mul, padding, convolution (conv, depthwiseconv, ∇conv_data, ∇conv_filter), pooling (maxpool, meanpool, lpnormpool) and upsampling (upsample_nearest, upsample_linear/bilinear/trilinear, pixel_shuffle); see Convolution, pooling and upsampling, and NNlib.gather and NNlib.scatter (+, -, mean). The Functors extension (TenferroFunctorsExt) makes EagerTensor, TracedTensor and eager scalars Functors.jl leaves, so fmap and fleaves treat each tensor as one value.
